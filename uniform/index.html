Wrapping logged-in web apps in one uniform UI

What survives adversarial verification, and what only looks like it does. 14 agents · 6 independent lenses · 10 disqualifying refutations · measured 2026-08-22 against Chrome 151.

THE VERDICT — a Manifest V3 extension, installed on the profile that already holds your sessions.
One measured fact decides it: extension install is the only CSP-exempt injection path. Tested against a page served Content-Security-Policy: default-src 'none'; style-src 'none' — the theme still applied. Nothing else clears that bar.

The cascade trap that breaks the obvious build

CSS Cascade 5 reverses @layer order for !important, so an unlayered !important is the weakest author-origin important — not the strongest. Measured against an app rule @layer appcomp{#t{color:rgb(1,1,1)!important}}, a theme lost all three ways: unlayered !important, adoptedStyleSheets + !important, and its own later @layer + !important. Real apps ship 30 @layer rules and 62 !important declarations.

✅ The fix: chrome.scripting.insertCSS({origin:'USER'}). USER-origin CSS outranks every author-origin rule — layered or not, important or not. The manifest css[] array is AUTHOR origin; keep it only for instant document_start paint, then re-deliver at USER origin from a service worker to win collisions.

⚠️ Unlayered still wins for plain token bindings. Both halves were measured; neither generalises, and a recommendation that states only one of them is wrong half the time.

Traps that cost real time

  • Bare HSL triplets. Some apps store colours as 0 0% 14.9% consumed via hsl(var(--t)). Writing a hex into one paints rgba(0,0,0,0) — fully transparent. Ship every colour twice: as hex and as channel triplet.
  • Read computed style, never stylesheet text. Most of an app's sheets are cross-origin unreadable — 8 of 11 in one measured case.
  • Relative url() resolves against the page origin, not the extension. Fonts and images need web_accessible_resources plus chrome.runtime.getURL().
  • The manifest css[] array is not resolved at the instant document_start JS runs. A boot script must read tokens lazily, never assume.
  • Shared chrome without an iframe: a closed-shadow custom element in the top layer via popover. Custom properties inherit through a closed shadow boundary, so one :root block themes the page and your bar while nothing leaks either way.
  • Durable selectors, in order: [data-testid] → [role] + [aria-label] → semantic id → structural. Hashed class names rot every deploy.
  • Never filter a live feed by walking the DOM. An unthrottled MutationObserver that re-queries the whole container on every mutation is O(feed × dom) — on a streaming page that is not slow, it is a locked main thread. Classify each row once, cache it on the node, process only added nodes, and coalesce bursts through requestAnimationFrame.
  • One human tap remains: "Allow User Scripts" is per-extension and defaults off. Policy pre-grant is unverified — do not promise it.

Two verification lessons, both learned the hard way

1. Confirm you measured the product, not a challenge page. One research lens reported a theme applied across "580 nodes" of a major app. Its own artifacts showed 35 nodes of a Cloudflare challenge page. It had measured the interstitial and called it the app — falling into a trap it documented itself one lens earlier.

2. Byte-identical delivery is not working software. A page can serve exactly the bytes you published, byte-for-byte verified, and the feature still do nothing — because nobody clicked it. A control that renders is not a control that works. The cheapest honest test is to drive the real surface and assert on the outcome: element count, computed value, and whether the page still answers afterwards.

Minimum manifest

{
  "manifest_version": 3,
  "name": "Uniform",
  "version": "0.1.0",
  "host_permissions": ["<all_urls>"],
  "permissions": ["scripting", "storage", "tabs"],
  "background": { "service_worker": "sw.js" },
  "content_scripts": [{
    "matches": ["<all_urls>"],
    "run_at": "document_start",
    "world": "ISOLATED",
    "css": ["tokens.css", "adapters.css"],
    "js":  ["chrome.js"]
  }],
  "web_accessible_resources": [
    { "resources": ["fonts/*.woff2"], "matches": ["<all_urls>"] }
  ]
}
Prove it in three steps — step 1 produces visible evidence:
  • chrome://extensions → Developer mode → Load unpacked. The card appears with an id.
  • Open a logged-in app. The injected bar renders, and you are still logged in.
  • Console: getComputedStyle(document.documentElement).getPropertyValue('--x-bg'). A non-empty value proves the token layer is live, not merely present.
Add "key" to the manifest to pin the extension id — without it an unpacked extension's id changes with its path. And note --load-extension does not persist across a profile relaunch; load once through the UI.
