02 · The fix68 subprocesses became one

The session-start hook blocks the first token. Inside it, a helper spawned one plutil per LaunchAgent plist to decide which daemons to reload — 68 serial subprocess spawns, about 55% of the whole hook.

# before — one subprocess per plist, 68 times, serial
dump="$(plutil -p "$plist")" || return 1
grep -qE '"(KeepAlive|StartInterval)" =>' <<<"$dump"

# after — one python process, plistlib, zero subprocesses on the fast path
with open(path,"rb") as fh: d = plistlib.load(fh)
persistent = any(k in d for k in PERSISTENT_KEYS)

03 · The trapA 19× speedup that would have broken six daemons

plutil is a lenient plist parser. Python’s plistlib is strict XML. Six of the 217 LaunchAgents contain a raw && inside a <string> — invalid XML, since & must be escaped. launchd and plutil accept them. plistlib refuses them.

universal-mcp-hub omniroute-gateway session-resume-watchdog daily-reply-catchup bin-script-check voice-id

Why the naive refactor is worse than the slow code

A plistlib-only rewrite silently reclassifies all six from persistent daemon to one-shot. The start-up wire then stops reloading them when they die — including the MCP hub — and nothing logs the decision. The speedup is real and the regression is invisible.

The shipped version tries plistlib first and falls back to plutil per file on any parse error: 211 fast paths, 6 slow ones, identical answers. A correctness gate comparing both classifiers over one frozen snapshot is what caught it — never swap a parser without one.

The control that mattered most was the quiet one

Four failure modes were forced: classifier deleted, classifier printing garbage, classifier exiting non-zero with empty output, and classifier intact. The third is the dangerous one — an empty result parses as “nothing to do.” Had the wire treated that as no dead daemons, it would have logged all daemons appear running and stopped reloading anything, forever, while reporting perfect health.

So the assertion is not DEAD > 0. It is never claim all-healthy while the list is empty. The bug is not an empty list — it is an empty list wearing a green checkmark.

05 · The methodAn instant is not a state

Four errors in one session, all the same mistake wearing different clothes.

  • A stale log read as silence. The speech log is written after playback finishes, so a tail that has not moved looks exactly like nothing was ever said. An outage was reported that never happened.
  • A cold run quoted as the number. First measurement 9.199 s; steady state 3.66–4.73 s. Take three before quoting a latency.
  • An A/B where the first run changed the second run’s world. The new code reloaded 52 dead daemons, so the old code — running seconds later — observed a different machine and appeared to disagree. Stateful comparisons need one frozen snapshot and zero side effects.
  • state = running on a job that runs one second in every three hundred. Sampled twice, nine minutes apart, opposite answers, both meaningless. For an interval job the honest probe is whether its output artifact is fresher than its interval — never the process table.

The through-line

Every one of these asked “what is it doing right now?” about something whose answer only means anything over an interval. A level and an instant are different measurements, and a green checkmark hides the difference perfectly.
