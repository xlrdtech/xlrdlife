SUIC·IDE

Sovereign User Interface Cognition

Pronounced "so-ik." Not a coding tool — a cognitive operating system, where written intentions in .self files turn directly into running processes and coordinated actions.

01What it is

"A unified development and execution environment purpose-built for Self-Executing 'living' programs… essentially a cognitive operating system where the user's written intentions directly turn into running processes and coordinated actions."

Formal definition · L7X System Architecture audit

SUIC collapses the boundary between writing down an idea and having that idea executed. The interface and the execution are the same thing. That is why its tagline is also the definition of Life Note: "you don't run programs… you write Notes, and they run you."

02The name decodes

Sovereign

Runs independently of external dependencies. The user is in full control — offline if needed. No cloud is required for it to work.

Interface

Interaction at a cognitive level, through text, voice or visuals — "keyboard, voice, and visual panes."

Cognition

The environment itself has awareness of context and intent. It is not a passive editor holding your text.

03The components

PartRole
SUIC SyntaxThe declarative notation you write intentions in. Human-readable, high-level — what to do, not how — and deliberately terse.
IDEThe front end. Text editor, voice interface, or visual canvas — or all three. Can be hosted in a browser Code-Server under SGOS.
SEL_The Self-Execution Lexicon — engine and vocabulary inside every .self. Creating a Note means implicitly using SEL_ to define what it does.
AgentsScoped sub-programs or personas declared inside a .self — an emailer, a page monitor — running in that Note's container and talking to each other.
STAXWatches for a saved .self and executes it immediately. No build step, no run command.
SPHIXThe invisible witness and memory logger. Records every significant change or decision — "gitless versioning, timeline-native memory, no commits."
DRXVXSync. Work offline, reconcile later.
Partitions 9_/7_Mode logic — 9_ for XLRDTECH execution, 7_ for business logic — so the same environment handles two scopes without bleeding between them.

A worked example from the source: a Note declares a ReportGen agent scheduled for 6 AM and an Emailer agent watching for a morning trigger. Saving the file is the entire deployment — at 6 AM ReportGen runs, fires the trigger, and Emailer sends. "All of this happens without further human intervention."

No external build tools, no cloud services, no manual triggers.

05Why a replacement, not a plugin

SPHIX alone answers this. An editor that logs every decision to timeline-native memory and needs no commits is not a feature you can bolt onto a tool built around a commit graph — it is a different model of what history means.

Assumption in every normal IDEWhat SUIC does instead
You write code, then run itWriting is running — STAX executes on save
Version control is explicit commitsSPHIX records continuously; no commits exist
The unit of work is a fileThe unit is a Note containing agents
Manifests are package.jsonautomanifests — a different format entirely
Input is a keyboardKeyboard, voice, and visual panes as equals
